# Feature Specification: 管理员手动维护 Skill（US-004）

**Feature Branch**: `codex/us-004-manual-maintenance`

**Created**: 2026-11-07

**Status**: Draft

**Input**: 用户确认进入 US-004（管理员手动维护）。依据上游 FR-005、FR-007、FR-009、NFR-003、
NFR-004、NFR-006、AC-006、AC-008、AC-011，Q-001 与 DEC-001/DEC-006/DEC-008 已确认的约束。

## 上游映射与范围

| 上游 | 本轮适用内容 | 证据 |
|---|---|---|
| FR-005 | 管理员通过 GitHub 后台上传单文件/目录、修改站点信息、显式替换、下架、配置来源；复用 GitHub 作为后台，不建站内专用后台 | AC-006 |
| FR-007 | 访客只读；写入仅管理员/授权 Agent；权限由 GitHub 控制；凭证与不可信内容边界 | AC-008 |
| FR-009 | 提交、构建、部署状态分开；失败保留旧站；恢复走受控历史 | AC-011 |
| NFR-003/004/006 | 无凭证泄露、无内容执行、失败保留、可复现操作说明 | AC-008、AC-011 |

**本轮不做**：Agent 命令行（US-005）、来源自动检查/调度（US-006）、站内上传后台或访客登录、
ZIP 解压上传、生产 Pages 源切换、自动更新开关的实际执行（仅记录配置字段与规划边界）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过 GitHub 后台上传并发布 Skill（Priority: P1）

管理员在 GitHub 仓库后台新增一个单文件或目录型 Skill，补充站内元数据记录并提交到默认分支；
发布流水线完成校验、构建与部署后，访客可在固定站点看到新条目并正常查阅、下载。

**Why this priority**：这是手动维护的最低可用闭环；没有它，管理员只能本地构建，无法安全上线。

**Independent Test**：在隔离副本或受控仓库提交一个合法单文件和目录型 Skill，验证校验、构建、
发布成功，站点索引/详情/下载出现该条目；不需要 Agent 命令或自动更新。

**Acceptance Scenarios**：

1. **Given** 管理员已具备仓库写权限，**When** 通过 GitHub 后台上传单文件 Skill 并补齐必要元数据后
   提交到默认分支，**Then** 流水线校验通过并发布，访客可看到该条目且原文/下载可用。对应 FR-005、AC-006。
2. **Given** 管理员上传目录型 Skill（含附件），**When** 提交内容与元数据，**Then** 目录结构、
   附件、许可和相对路径在站点与目录下载包中保持完整。对应 FR-005、AC-006。
3. **Given** 管理员只修改站内显示名、标签、备注或来源信息，**When** 提交元数据变更，
   **Then** 站点信息更新，原件字节不被改写。对应 FR-005、FR-007。
4. **Given** 新增内容合法，**When** 发布成功，**Then** 公开页面只显示内容本身的同步信息，
   运行日志和内部错误不进入访客页面。对应 FR-009、AC-011。

---

### User Story 2 - 非法或不完整输入整批阻止且旧站保留（Priority: P1）

管理员提交的批次中只要有一项非法（缺必填字段、路径越界、附件缺失、疑似凭证或超限），
整次发布被阻止；已上线站点保持可读，管理员能从运行记录定位到具体条目和字段。

**Why this priority**：手动维护是主要写入路径，必须保证一次错误提交不会破坏现行站点。

**Independent Test**：在隔离副本或受控仓库提交含缺失附件/非法元数据/凭证文件的批次，确认构建失败、
无部署、旧站点与旧产物不变，诊断只报告位置与规则。

**Acceptance Scenarios**：

1. **Given** 批次包含缺失必填元数据的条目，**When** 提交并触发校验，**Then** 整批失败并指出字段位置，
   不生成可部署的残缺站点。对应 FR-005、FR-009。
2. **Given** 批次包含越界路径、缺失附件、凭据文件或超限文件，**When** 校验/构建执行，
   **Then** 整批失败、不部署，诊断不回显文件内容或凭证。对应 FR-007、NFR-003。
3. **Given** 上一版本站点已在线，**When** 新批次失败，**Then** 旧站继续可读，旧索引/详情/下载不被覆盖。
   对应 FR-009、AC-011。

---

### User Story 3 - 显式替换、下架与受控恢复（Priority: P2）

管理员对已存在的 slug 执行显式替换（不同内容不得静默覆盖），或下架某个 Skill；替换后仍只有一个
当前版本，下架后索引、详情和下载同步移除；需要回到旧内容时通过受控历史恢复提交重新发布。

**Why this priority**：维护不仅是新增；替换/下架与恢复决定内容正确性和可回退性。

**Independent Test**：在隔离副本或受控仓库替换同一 slug 的内容并检查单版本；下架后检查索引/详情/
下载消失；用受控 revert 重建并确认既有 slug 与旧链接保持。

**Acceptance Scenarios**：

1. **Given** 已存在 slug `example`，**When** 管理员以不同内容显式替换并提交，
   **Then** 该 slug 仍只有一个当前版本，旧附件按新内容清单清理。对应 FR-005、AC-006。
2. **Given** 管理员未声明替换而提交了同 slug 的不同内容，**When** 校验执行，
   **Then** 返回冲突并保留当前内容，不静默覆盖。对应 FR-005、FR-009。
3. **Given** 管理员下架某 Skill，**When** 发布完成，**Then** 公开索引、详情和下载不再包含该条目，
   未纳管文件不受影响。对应 FR-005、AC-011。
4. **Given** 需要恢复上一份有效内容，**When** 管理员使用受控历史恢复提交并重新构建发布，
   **Then** 既有 slug、旧链接和单版本保持，历史不被强制改写。对应 FR-009、AC-011。

---

### User Story 4 - 可见但低权重的管理入口与权限边界（Priority: P2）

站点提供低权重的“管理”外链指向 GitHub 仓库，访客无需登录即可只读；不存在站内上传表单、
隐藏路径授权或浏览器凭证。未授权身份无法产生写入或发布副作用。

**Why this priority**：入口必须可发现但不能暗示站内登录或扩大权限面。

**Independent Test**：检查站点管理外链与只读行为；以未授权身份尝试写入/触发发布，确认失败且无副作用。

**Acceptance Scenarios**：

1. **Given** 访客浏览任意页面，**When** 查看管理入口，**Then** 入口指向受信任仓库后台，
   不出现站内登录或上传表单。对应 FR-007、AC-008。
2. **Given** 未授权身份或无凭据来源，**When** 尝试提交/触发发布，**Then** 请求失败且不产生仓库、
   产物或线上副作用。对应 FR-007、AC-008。
3. **Given** 管理员或授权 Agent 执行手动维护，**When** 提交发布，**Then** 与命令行等其他入口
   共用同一校验与发布规则，不因调用者不同而绕过检查。对应 FR-007、AC-006。

### Edge Cases

- 缺必填字段、未知字段、字段类型错误：给出字段级诊断，不静默丢弃或猜测。
- 单文件与目录型 slug 相互替换：必须显式声明并提供完整新内容，旧附件清理，不累积版本。
- 上传包含脚本、Agent 配置或可执行说明的第三方 Skill：只作为数据保存与展示，不执行、不安装依赖。
- 上传包含疑似凭证的文件或元数据：整批失败，只报告位置与规则。
- 批次含多项时部分非法：整批阻止，不发布部分成功内容；其他合法条目可单独重提。
- 上传中断、重复提交、并发修改：不产生部分写入；同内容重复提交为无变化；不同内容需显式替换。
- 下架后旧分享链接：返回列表/未找到状态，不残留索引或下载；Git 历史仍可用于恢复。
- 超过文件数量/大小限制、符号链接、绝对路径或隐藏凭证目录：拒绝并报告。
- 生产 Pages 未启用或权限不足：明确失败，不降低分支保护或扩大权限。
- 运行记录不可读或 artifact 过期：说明限制，以最新运行结果为准，不声称永久审计。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-005（本轮）**：管理员 MUST 能通过 GitHub 仓库后台新增单文件或目录型 Skill、修改站内元数据、
  显式替换、下架及配置来源信息；系统 MUST 复用 GitHub 文件管理与 Actions，不新增站内上传后台、
  数据库或访客登录。目录 MUST 可按文件夹上传，MUST NOT 要求首版支持 ZIP 解压。缺少必填字段时
  MUST 给出补充方式；批量提交含非法项时 MUST 整批阻止发布，已上线内容 MUST 保持可读；下架 MUST
  从当前索引、详情和下载移除，不处理未纳管文件。**验收**：User Story 1～3；AC-006。
- **FR-007（本轮）**：公开读取 MUST 保持只读；上传、替换、下架、改来源、触发更新及发布 MUST 仅由
  管理员或授权 Agent 在受信任环境执行，身份 MUST 复用 GitHub 权限与既有 Git/gh 授权；隐藏入口
  MUST NOT 作为权限控制。未授权尝试 MUST NOT 产生仓库、产物或线上副作用。凭证 MUST 不进入页面、
  产物、日志或示例；第三方 Skill MUST 作为不可信数据处理，不执行其脚本或安装依赖。手动维护与
  其他入口 MUST 共用同一校验与发布规则。**验收**：User Story 2、4；AC-008、AC-012 的发布路径。
- **FR-009（本轮）**：每次手动维护 MUST 分别记录内容提交、构建与部署状态，并提供可定位的运行标识
  和失败原因；失败 MUST 保留上次正常站点；替换 MUST 保持单版本；恢复 MUST 通过受控历史恢复提交
  重新构建发布，保持既有 slug 与旧链接，不清除或强制改写历史。公开页面 MUST 只展示最近成功同步
  信息，不展示运行日志或内部错误。**验收**：User Story 1～3；AC-011。
- **FR-010（本轮）**：管理入口 MUST 为低权重外链，指向受信任仓库后台；MUST NOT 呈现访客登录表单
  或站内上传能力。**验收**：User Story 4；AC-008。

**适用非功能需求与验收边界**：

| 上游 ID | 本轮适用规则 | 本轮验收 | 留给后续的部分 |
|---|---|---|---|
| NFR-003 | 无匿名写、无凭证泄露、无内容执行或路径越界；产物白名单 | AC-008 的手动维护路径 | Agent CLI 鉴权细节由 US-005 承担 |
| NFR-004 | 失败不毁当前版、重试幂等、并发不覆盖、结果可观察 | AC-011 的手动维护路径 | 自动来源检查失败矩阵由 US-006 承担 |
| NFR-006 | 干净 checkout 可复现、操作说明可独立执行 | 管理员说明在干净环境可执行 | 完整 Agent 命令说明由 US-005 承担 |

**上游 AC 映射**：

| 上游验收 | 本轮操作与证据 | 覆盖声明 |
|---|---|---|
| AC-006 | 合法新增/替换/下架/元数据修改、非法项整批阻止、失败保留 | 覆盖 GitHub 手动维护路径；不覆盖 Agent CLI |
| AC-008 | 访客只读、未授权无副作用、凭证不回显、内容不执行 | 复用发布链证据并补充手动入口断言 |
| AC-011 | 提交/构建/部署分离、失败保留、恢复提交、单版本 | 覆盖手动维护与恢复路径 |

### Key Entities

- **手动维护操作**：管理员对某 slug 的新增、元数据修改、显式替换或下架；包含操作类型、目标 slug、
  内容文件、站内记录和可追踪的提交标识。
- **站内内容记录**：与原件分离的显示名、简介、标签、平台、来源、用法、备注等；必填字段缺失必须
  可诊断。
- **维护结果**：内容提交状态、构建状态、部署状态、失败原因、运行标识和恢复入口；三者不得合并为
  单一成功/失败。
- **权限上下文**：访客、未授权身份、管理员/授权 Agent；决定是否允许写入与发布。
- **恢复记录**：受控历史恢复提交及其重新构建发布结果，保持既有 slug 与旧链接。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **US004-SC-01**：合法单文件与目录型 Skill 通过 GitHub 手动提交后，100% 完成校验、构建和部署，
  公开索引/详情/下载均可访问。
- **US004-SC-02**：含缺失字段、越界路径、缺失附件、凭证或超限文件的批次 100% 阻止部署；
  失败批次造成的线上变更次数为 0，旧站点保持可读。
- **US004-SC-03**：替换后同一 slug 的当前版本数恒为 1，旧附件清理率 100%；下架后索引、详情和下载
  命中数为 0。
- **US004-SC-04**：公开产物、页面、日志和示例中的凭证回显为 0；收录 Skill 的脚本执行次数为 0。
- **US004-SC-05**：管理员仅按说明操作即可完成新增/替换/下架；失败时能在运行记录中定位到条目与字段，
  不需要站内后台或登录。

## Assumptions

- 管理员已具备 GitHub 仓库写权限；访客无需账户；身份与授权由 GitHub 及既有 Git/gh 会话控制（Q-001）。
- 生产 Pages 源切换、environment 审批和线上发布需单独授权；本轮验收可在隔离副本或受控临时仓库完成。
- 目录按文件夹上传由 GitHub 后台提供；ZIP 解压、批量脚本和 Agent 命令属于后续故事（US-005）。
- 自动更新来源配置字段可以手动维护，但实际检查、调度与替换属于 US-006；本轮不承诺自动更新能力。
- 现有构建、产物校验与发布链（US-003）作为手动维护的执行基础；本故事不改变内容 schema、搜索/详情
  前端行为或固定地址。
- 生产启用前不得把本地/受控验证报告为线上发布成功。
