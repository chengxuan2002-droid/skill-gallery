## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只发布同一内容快照的合法静态产物（US-003.A，Priority: P1）

作为维护者，我希望每次发布前都完整校验全部内容，并只部署一份来自同一快照、仅含允许公开文件的静态产物，
以便访客看到的内容、索引、详情和下载彼此一致，且错误输入不会污染线上站点。

**Why this priority**: 没有可信的全量校验与白名单产物，后续手动维护、命令提交和自动更新都会把错误放大到线上。

**Independent Test**: 在隔离副本使用合法与非法夹具执行完整校验、构建和产物检查，验证白名单、同一快照、
固定地址子路径、四个旧详情链接和刷新；不依赖生产凭证或真实 Pages 配置。

**Acceptance Scenarios**:

1. **Given** 合法内容树和干净环境，**When** 执行一次发布准备，**Then** 全部条目通过校验并生成
   仅含公开静态文件的产物；页面、索引、详情、原件和下载包来自同一内容标识。对应 FR-011、AC-014。
2. **Given** 任一非法条目、缺失附件、非法元数据或路径越界，**When** 执行发布准备，
   **Then** 整批失败且无部署发生，已有线上内容保持可读，失败提供可定位的诊断。
   对应 FR-009、FR-011、AC-014。
3. **Given** 产物中混入规划资料、交接记录、Git 数据、工具配置、后台日志、凭证或不允许的链接文件，
   **When** 执行发布前检查，**Then** 该产物被拒绝部署，不以“构建成功”放行。对应 FR-007、NFR-003、AC-008。
4. **Given** 合法产物部署到固定站点，**When** 访客访问首页、`/skill-gallery/` 资源、四个旧
   `#/skill/<slug>` 链接并刷新，**Then** 页面可读且身份保持，子路径资源无 404。对应 FR-011、AC-014。
5. **Given** 站点内容未变化，**When** 再次运行发布准备，**Then** 不产生无意义的新内容提交；
   允许重新部署同一内容快照并记录为同一 `contentRevision` 的真实运行，不把重复部署伪造成内容更新；
   若线上落后于当前提交，也可显式重发当前快照。对应 FR-009、AC-014。

### User Story 2 - 发布失败保留上次可用站点并可恢复（US-003.B，Priority: P1）

作为维护者，我希望提交、构建和部署的状态分别可见，部署失败时线上仍保持上一份正常站点，
并能按同一份已提交内容重跑或通过受控历史恢复，以便不把失败伪装成成功，也不重复制造内容提交。

**Why this priority**: 静态站点发布不是跨系统原子事务；只有明确区分状态并保留可用版本，维护者才能安全重试。

**Independent Test**: 在隔离/受控环境注入构建失败、部署失败、并发运行和旧运行回写，检查线上可用性、
状态区分、重跑幂等与恢复提交；不修改真实生产配置。

**Acceptance Scenarios**:

1. **Given** 内容已提交但部署失败，**When** 维护者查看运行状态，**Then** 明确显示“提交成功、部署失败”，
   线上保持上次正常快照，不报告整体成功。对应 FR-009、AC-011。
2. **Given** 同一提交的重跑请求，**When** 重新执行部署，**Then** 不新建内容提交，重跑幂等，成功后状态变为已发布。
   对应 FR-009、AC-011。
3. **Given** 两个运行并发或旧运行晚到，**When** 它们尝试发布不同快照，**Then** 运行被串行化或标记为已过期，
   旧快照不得覆盖新快照。对应 FR-009、NFR-004、AC-011。
4. **Given** 需要回到上一份有效内容，**When** 维护者按受控历史生成恢复提交并重新发布，
   **Then** 既有 slug、旧链接和单版本语义保持，不强制改写或清除 Git 历史。对应 FR-009、AC-011。
5. **Given** 无变化、部署失败和成功发布三类运行，**When** 维护者查看记录，
   **Then** 可区分运行时间、内容提交、构建/部署结果和运行标识，不把无变化检查伪造成更新。
   对应 FR-009、AC-011。

### User Story 3 - 写入与部署仅限受信环境（US-003.C，Priority: P1）

作为站点所有者，我希望访客无需登录即可读取，但只有已授权维护者或 Agent 才能触发提交、构建和部署，
凭证与不受信内容都不进入页面、产物或日志，以便公开站点不因自动化而出现匿名写入或密钥泄露。

**Why this priority**: 复用 GitHub 后台与 Actions 的前提是权限边界和凭证隔离；否则发布流水线本身会成为攻击面。

**Independent Test**: 使用未登录访客、无权限身份、授权身份和 fork/不受信 PR 模拟触发写入与部署，
检查副作用、产物与日志；不执行收录 Skill 的脚本，不使用真实凭证。

**Acceptance Scenarios**:

1. **Given** 未登录访客，**When** 浏览、搜索、下载和分享，**Then** 全部可用且不需要账户。
   对应 FR-007、AC-008。
2. **Given** 无写权限身份或不受信来源，**When** 尝试上传、替换、触发构建或部署，
   **Then** 请求失败且不产生仓库、产物或线上副作用。对应 FR-007、AC-008。
3. **Given** 已授权维护者或 Agent，**When** 触发发布，**Then** 按同一校验与发布规则执行，
   不因调用者不同而绕过检查。对应 FR-007、AC-008。
4. **Given** 产物、日志和运行报告，**When** 执行凭证与敏感信息检查，
   **Then** 不含密码、token、cookie 或密钥值；诊断只报告位置与类型。对应 FR-007、NFR-003、AC-008。
5. **Given** 收录的第三方 Skill 含脚本、Agent 配置或可执行说明，**When** 校验、构建和发布，
   **Then** 这些内容只作为数据处理，不被执行或安装依赖。对应 FR-007、AC-008、AC-012。

### User Story 4 - 自动提交后的显式发布衔接（US-003.D，Priority: P2）

作为维护者，我希望未来自动更新产生的提交能在同一次运行中显式进入构建与部署阶段，
而不是依赖另一次隐式的 push 触发，以便自动提交与线上切换可以被追踪、重试和判定失败。

**Why this priority**: US-006 的自动更新依赖这一衔接；本故事只提供发布入口与验证，不实现来源检查本身。

**Independent Test**: 在受控环境模拟一次自动提交（或等价的机器提交），从同一运行显式调用构建与部署，
检查内容提交、产物与线上切换的对应关系；不启用生产定时任务。

**Acceptance Scenarios**:

1. **Given** 一次机器提交产生了新的当前内容，**When** 同一运行准备发布，
   **Then** 该运行显式构建并部署对应提交，不等待其他 push 事件。对应 FR-009、FR-011、AC-014。
2. **Given** 机器提交没有实际内容变化，**When** 运行完成，**Then** 不创建空内容提交；
   允许重复部署同一快照，但状态必须保留同一 `contentRevision`，不把无变化检查伪造成内容更新。
   对应 FR-009、AC-011、AC-014。
3. **Given** 显式发布失败，**When** 维护者重试，**Then** 以同一目标提交重跑，不依赖新的内容提交，
   并保留上次正常站点。对应 FR-009、AC-011、AC-014。
4. **Given** 当前分支受保护或机器人无写入权限，**When** 运行尝试提交或部署，
   **Then** 失败被明确报告，不通过降低分支保护或扩大权限绕过。对应 FR-007、AC-008、AC-014。

### Edge Cases

- 空库、单条内容、四项内容与未来更多内容：校验、构建与发布规则一致，不因规模变化跳过检查。
- 无变化运行、重复运行、同一提交重跑：均为 noop 或幂等，不制造空内容提交；重复部署同一快照可接受。
- 构建被中断、遗留候选目录、锁文件或临时状态：失败关闭，保留上次有效站点，恢复路径明确。
- 产物检查发现缺失文件、额外文件、链接文件、凭证或不允许的扩展名：拒绝部署并报告位置。
- 部署失败、环境审批未通过、部署超时或平台限流：状态为失败或等待，不伪造发布成功。
- 并发运行、旧运行晚到、手动与自动同时触发：串行化或标记过期，旧快照不得覆盖新快照。
- 分支保护拒绝机器人写入、权限不足或凭证过期：无部分写入，报告未授权或冲突。
- 固定地址、子路径、旧详情链接、刷新和直接打开详情：部署后保持可用；失败时不切换。
- 产物过期、运行记录不可读或历史明细已清理：明确说明限制，以最新运行结果为准，不声称永久审计。
- 自动提交后的运行与内容提交分离：同一运行可显式衔接构建与部署，不依赖隐式 push 链。
- 收录内容含活动 HTML、危险 URL、越界路径或脚本：仅作为数据处理；发布产物不执行也不暴露活跃内容。
- 线上 MIME、缓存和直接资源响应与预览环境不同：发布前记录为待验证项，不以本地预览结果代替线上检查。
- 生产环境未授权、凭据不可用或测试仓库不存在：只交付可审阅配置与本地验证，明确记为未运行。

### Key Entities

- **内容快照**：一次构建读取的原件、图库记录与内容标识；页面、索引、详情和下载必须共享同一身份。
- **构建产物**：仅含允许公开的静态文件及其清单；被拒绝的路径、凭证和链接文件不得进入。
- **运行记录**：运行标识、操作者/触发方式、目标提交、构建与部署状态、失败原因和可重试入口。
- **部署状态**：未开始、构建中、部署中、已发布、失败、等待或已过期；必须能与内容提交状态分开表达。
- **权限上下文**：访客、无权限身份、授权维护者/Agent、不受信来源；决定是否允许写入与部署。
- **恢复记录**：用于回到上一份有效内容的受控历史提交及对应重新发布结果。
