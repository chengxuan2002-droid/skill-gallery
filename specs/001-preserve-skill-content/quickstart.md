# US-001 实施后验证指南

创建：2026-11-01；分析后修订：2026-11-02。依据 [spec](spec.md)、[plan](plan.md)、[数据模型](data-model.md)、
[内容契约](contracts/content-pipeline.md)、[静态契约](contracts/static-site.md)。

**业务验收仍为规划**：根 package、工程测试、安全检查及 tasks 已建立；下列业务迁移、构建、preview
和业务测试尚未实现。换电脑恢复工程环境见根 README；不把工程检查或文档生成视为 AC 通过。
后续先复核 spec/plan/tasks 一致性，再经授权实现；完成后才按此指南验收。
本指南不包含上传、Git 提交、自动更新、工作流或部署命令。

## 1. 环境与安全前提

- 使用 Node 26.3.0 本地基线和实现后的精确 package-lock；不需要 Python、GitHub token 或生产权限。
- 在包含同一实现版本的隔离项目副本验证，保留用户工作区和未跟踪 office2md。若实施尚未提交，应明确复制受控实现文件，不能只 clone 旧 HEAD 后当成新实现。
- 原件仅为数据；不执行 skills 下脚本，不安装其 package/requirements。测试发现只指向受信任 tests/unit 与 tests/integration。
- 先记录 spec 中四项、六文件的路径/大小/SHA-256/执行位基线。任何日志只能输出位置、摘要和类型，不能打印疑似凭证。

~~~bash
# 在待验证的项目副本根目录执行
node --version
git status --short
~~~

预期识别正确 Node 及已有改动，不能 reset/clean 用户文件来“准备环境”。

## 2. 实施完成后的命令

仅在这些入口真实存在并由实现任务验证后执行：

~~~bash
npm ci
npm test
node scripts/migrate-catalog.js --dry-run
npm run build
npm run preview
~~~

| 命令 | 用途 | 预期结果 |
|---|---|---|
| npm ci | 按锁文件安装站点受信任依赖 | 版本符合 research；不能递归安装收录 Skill 的依赖 |
| npm test | Node 单元/内容集成/契约验证 | 显式 tests/unit/*.test.js 与 tests/integration/*.test.js 全通过；不执行 skills 中测试 |
| migrate-catalog --dry-run | 四项旧库迁移预览 | 恰好四项，已有一致记录为 noop；不写入任何文件 |
| migrate-catalog --write | 仅在需创建记录的隔离迁移副本使用 | 全部合法才新增四记录，不改原件；不同现有记录冲突且零覆盖 |
| npm run build | 完整校验并构建 dist | 提交成功退出 0/built，报告 cleanup_status=complete 或 pending；提交前失败退出 1；不再写根 assets/search-index.json，不报告 published |
| npm run preview | 只读预览 dist | 监听 localhost:8000，仅映射 /skill-gallery/；不是部署 |

预览地址：[本地站点](http://localhost:8000/skill-gallery/)。
关闭服务用 Ctrl+C。普通 python http.server 项目根预览不能替代本次子路径和公开目录边界验证。
若目录/命令缺失，应返回实施任务补齐，不能把现有旧索引构建的成功当成新能力。

macOS 与 Linux 分别核对 ZIP 路径/权限与 rename 回滚；没有环境的部分必须记录“未运行”，不能报完整跨平台通过。

## 4. 浏览器验证

使用现代浏览器或已有可信浏览器工具；本轮不新增 E2E 框架。记录浏览器版本、测试地址、
必要截图、实际下载文件及 SHA-256/解包比对结果，不用截图代替字节证据。

1. 从本地站点打开四个旧详情链接，逐一刷新，再复制分享链接访问。slug 一致、基本列表/查阅可用，资源/下载始终位于 /skill-gallery/。
2. 查看完整原文，核对 frontmatter、未知字段、代码、中文与完整正文；复制原文检查内容完整。单文件按原名 .md 下载并与源摘要比对；handoff-codex ZIP 含 SKILL.md、agents/openai.yaml、scripts/create_handoff.sh，路径/字节/执行意图符合契约。
3. 进入隔离样例详情，检查表格、代码和相对附件可访问；安全栅格图片显示，SVG/活动附件为下载入口，不以网页/iframe 打开。点击中文/重复标题的本文锚点，确认定位正确、当前 #/skill/<slug> 不变；未知片段明示不可跳转，伪造 id/name 无效。查看原文使用文本区域，无脚本或哨兵执行。
4. 阻止剪贴板权限（或由可信浏览器工具模拟 writeText 拒绝），点击复制：明确失败，原文/链接仍可手动复制，零成功提示。
5. 在浏览器网络面板阻断目标 .bin/.zip，或使用隔离的损坏输出副本，检查下载失败与原文不可用；不能保存 404 页面或报已成功。
6. 访问未知 slug、损坏/不支持 schema 的独立输出副本，检查可识别错误。快速切换两个详情，不能显示上一个请求迟到的内容。
7. 在隔离目录手工准备同 slug 第二快照并完整重建，旧链接仍指向该身份；过期索引与新详情混读时阻止取用并提示刷新。此操作不是管理员替换入口或自动升级功能。
8. 检查本地 .bin 响应为 application/octet-stream、直接访问不作为活动 HTML，预览服务不能读取 dist 外文件。本结果只代表本地，生产响应头须由 US-003 复核。

## 5. 本地中断恢复（仅实施后）

以 [C-03 本地协议及恢复表](contracts/content-pipeline.md#local-recovery) 为准，不另建一套恢复逻辑：

1. 发现 .dist.lock 时核对 owner 的 run_id/pid；进程仍活动、无法证实已退出或 owner 损坏时，不按超时抢锁、不删除输出。
2. 人工确认原构建已退出并核对 owner（若有事务再核对 run_id 对应关系）后，仅解除匹配锁；保留 .dist.transaction.json、stage 和 backup，随后重跑 npm run build。没有事务也不能顺带删除候选。不要先删除 dist、backup 或事务记录。
3. 新构建取得新锁后，按旧事务 run_id 派生路径、验证 manifest/产物摘要并逐行恢复；prepared/promoting 不悄悄当作已提交，promoted 不回滚有效新 dist。
4. cleanup_status=pending 表示本次构建已提交且结果可用但清理未完成；保留记录供后续检查。启动恢复未结束旧事务则退出 1/E_RECOVERY_REQUIRED，不能覆盖记录或宣称新构建 built。记录损坏、部分 backup 无法验证、额外文件或恢复失败时停止自动处理，保留有效输出等待人工核对。

恢复记录/锁/随机标识不进入 dist、业务日期或内容身份。只验证本地中断恢复，不宣称断电连续可用或生产回滚已完成。

## 6. 报告与范围复核

报告至少包含：实现版本、Node/浏览器/平台版本、实际命令与退出码、四项源清单摘要、
下载/解包差异数、提交前失败时原件/旧输出变化数、恢复表逐行结果与提交后清理状态、
标题锚点/Hash 与固定凭证规则证据、产物白名单结果、未运行项与残留风险。

逐项映射 US001-SC-01～07；AC-001/002 为本故事迁移与完整取用验收；
AC-005 只报告链接/反馈；AC-012 只报告本地处理；AC-014 只报告本地前缀/同快照。
不以本地 built 或模拟同 slug 快照宣称已上传、自动更新、完成生产部署或完成 US-002 全站搜索/视觉。

后续发布前还需实际 Pages MIME/直接资源安全、缓存一致性、授权与发布恢复验收；自动更新启用前另解决 Q-004。
这些不阻塞本故事本地规划，也不能被本轮验收报告勾成已完成。
