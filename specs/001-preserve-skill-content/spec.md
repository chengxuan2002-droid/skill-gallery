## User Scenarios & Testing *(mandatory)*

### User Story 1 - 保留既有收藏并分离图库信息（US-001.A，Priority: P1）

作为维护者，我希望把现有四项 Skill 迁移到能完整保存内容的图库中，
在不改动原文和附件的前提下保留其名称、分类、个人备注及分享身份，避免收藏丢失或被静默遗漏。

**Why this priority**: 四项既有收藏是本轮兼容基线；完整迁移才能避免以新增功能为代价破坏已收录内容。

**Independent Test**: 仅使用四项原文件及其附件和一个合法标准格式样例完成隔离迁移，
核对条目、信息、路径与字节，无需上传后台、自动更新或生产站点即可验收。

**Acceptance Scenarios**:

1. **Given** 下表四项基线及其全部受控附件，**When** 维护者迁移并生成本地可查阅结果，
   **Then** 恰好得到四个唯一 Skill，slug、原文及附件逐一对应，原件字节与相对路径保持不变。
   对应 AC-001、NFR-001。
2. **Given** 仅含标准名称和简介的合法 Skill，含折叠/多行简介及未知扩展字段，
   **When** 维护者补充站内显示信息并生成结果，**Then** 它可以被纳入独立样例库，
   不因缺标签、平台等图库专属字段被静默跳过；扩展字段与原始文档保持完整。
   对应 FR-001、AC-001、AC-002；该样例不自动成为正式第五项收藏。
3. **Given** 站内备注、标签、显示名称与原文存在不同值，**When** 更新站内信息并重新生成结果，
   **Then** 原件不变，站内信息可独立保存和展示；未知作者、地址或版本明确标为未提供，不被编造。
   对应 FR-001、AC-002。
4. **Given** 原有四个详情链接，**When** 打开迁移后的本地预览并访问这些链接，
   **Then** 每个链接仍指向原 Skill，现有列表和基本查阅入口仍可使用。
   对应 FR-011、AC-005 的迁移兼容部分。

**既有收藏基线**:

| 稳定 slug | 原始主文档 | 主文档之外的受控附件 |
|---|---|---|
| `superpower-systematic-debugging` | `skills/superpower-systematic-debugging.md` | 无 |
| `code-review-assistant` | `skills/code-review-assistant.md` | 无 |
| `refactoring-workflow` | `skills/refactoring-workflow.md` | 无 |
| `handoff-codex` | `skills/handoff-codex/SKILL.md` | `agents/openai.yaml`、`scripts/create_handoff.sh` |

基线在实施开始时记录实际源文件清单和内容摘要，不能用现有有损索引恢复正文。
本地未跟踪的 `office2md` 和其他未明确收录的文件不属于这四项，必须保持原状且不被自动入库。

### User Story 2 - 完整查阅、复制和下载（US-001.B，Priority: P1）

作为访客，我希望从既有详情入口查看原文、复制完整文档，或下载完整 Skill，
以便在自己的 Agent 环境中使用，而不是得到缺失代码、版本或脚本的节选。

**Why this priority**: 内容保真只有在访客真正取得完整文件时才有价值，本轮必须形成从收藏到取用的最小闭环。

**Independent Test**: 给定一个单文件 Skill 和一个目录型 Skill 样例，
在基本详情入口中查看、复制、下载并核对结果，不依赖四项迁移全部完成或其他功能上线。

**Acceptance Scenarios**:

1. **Given** 含 frontmatter、版本、未知字段、中文和代码块的主文档，
   **When** 访客查看原文并复制完整文档或下载单文件原件，
   **Then** 完整文档含原始 frontmatter 和正文；单文件下载保留原名和原始字节，
   不能用检索用纯文本重建。对应 AC-002。
2. **Given** 目录型 Skill 含主文档、嵌套脚本、参考资料、许可及二进制资源，
   **When** 访客下载完整目录包并解包，**Then** 包内以该 Skill 目录为根，入口为 `SKILL.md`，
   所有应收录附件路径与字节一致，许可保留且不混入其他 Skill 或项目文件。
   对应 FR-004、NFR-001、AC-002。
3. **Given** 正文含代码块、列表、表格及指向当前 Skill 附件的合法相对链接，
   **When** 访客查阅本轮基本详情，**Then** 内容可读，代码不丢失，相对附件可以正确访问；
   展示处理不改变下载原件。对应 AC-002、AC-012 的原文展示部分。
4. **Given** 既有 `#/skill/<slug>` 链接与 `/skill-gallery/` 访问前缀，
   **When** 访客直接访问、刷新或复制分享链接，**Then** 同一 Skill 身份保持，正文及下载可达，
   不跳转至错误根路径。对应 AC-005；本轮通过本地等价前缀预览验收，不执行生产发布。
5. **Given** 复制权限被拒绝或下载文件无法取得，**When** 访客执行相应操作，
   **Then** 操作明确报告失败；复制失败保留可手动复制的原文，不显示成功提示。
   对应 AC-005、FR-004。

### User Story 3 - 非法内容不破坏已有收藏（US-001.C，Priority: P1）

作为维护者，我希望非法内容或不安全附件被明确拦截，知道需要修正的位置，
同时原件和已有可用结果保持不变，避免错误数据导致静默丢项或泄露项目文件。

**Why this priority**: 安全边界和失败保留是本轮内容处理的前提，不能等到上传和自动更新阶段再补。

**Independent Test**: 使用隔离的合法与非法样例检查错误报告、既有结果及执行副作用，
无需创建管理接口、远程凭证或执行任何收录脚本。

**Acceptance Scenarios**:

1. **Given** 缺主文档、必填名称/简介为空、字段类型错误或无法解析的元数据，
   **When** 维护者校验或重建图库，**Then** 明确失败并指出条目与原因，
   不生成被当作成功的残缺结果、不修改原件或替换上次有效结果。对应 FR-001、FR-011、AC-001。
2. **Given** 两份输入使用同一 slug 或来源无法唯一对应，**When** 重建结果，
   **Then** 报告冲突，不选择其中一个默默覆盖，也不产生重复条目。对应 AC-001。
3. **Given** 附件包含越界路径、绝对路径或链接型文件，**When** 处理和打包该 Skill，
   **Then** 拒绝非法输入，不读取或打包 Skill 范围之外的文件，原件和已有有效结果保持不变。
   对应 AC-012 的当前内容处理部分。
4. **Given** 原文包含活动 HTML、事件属性或危险地址，另有合法可执行脚本附件，
   **When** 预览、复制或下载原件/完整包，**Then** 页面不执行活动内容，
   收录和取用过程不运行脚本，合法脚本仅作为文件保真交付；原始文档保持原样。
   对应 AC-012、NFR-003。
5. **Given** 文件名或位置提示可能包含凭证、私人配置或项目内部资料，
   **When** 校验并生成可分发结果，**Then** 将不允许分发的输入拒绝或排除于明确的收录范围，
   报告只给出位置和类型，不回显凭证值；已允许收录的内容不得静默删减。
   对应 NFR-003、宪章原则 III、VII。
6. **Given** 正文引用了不存在或越界的附件，**When** 校验并查阅，
   **Then** 缺失本地附件属于致命校验错误，整次生成失败，报告条目及缺失引用，
   保留原始文件和上次有效结果，不提供本次不完整预览或下载；
   越界引用不得解析为其他 Skill 或项目文件。
   对应 AC-012；合法外部资料链接不能被误认为本地缺失附件。

### Edge Cases

- 主文档存在但为空、元数据不合法、字段类型错误：区分错误原因，不用默认值掩盖非法结构。
- 合法主文档只有名称和简介：允许标签、平台为空；作者、声明版本和官方地址缺失时不编造。
- frontmatter 使用折叠、多行和嵌套扩展字段：允许读取信息，但原文及未知字段不得丢失。
- 旧文件的显示名称含中文或与 slug 不同：保留站内身份，不为迎合新命名格式重写原件。
- 附件有多层目录、空格、中文文件名或二进制内容：保留相对路径及字节，不按文本重写。
- 以点开头的合法资源与系统/凭证文件：按明确的收录范围区分，不能把全部点文件直接打包，
  也不能静默漏掉 Skill 所需的合法资源；计划阶段明确可执行的边界规则。
- Skill 无附件时仍可取用主文档；目录包不能因没有附属脚本而失败。
- 正文引用的本地附件缺失：整次生成失败并报告具体条目及引用，原始文件和上次有效结果不变，
  不提供本次不完整预览或下载；合法外部网址不按本地附件缺失处理。
- 相同数据重复生成：条目、原文及附件不增加、不变更，不产生伪造版本或更新时间变化。
- 原文含活动内容但文件本身合法：限制页面展示行为，原件下载仍保真；非法结构输入则拒绝。
- 生成中途发生错误：保留原始收藏和上次有效结果，不能留下被声明为成功的半成品。
- 未知 slug、原文或下载不可用：显示可识别的未找到/不可用状态，不错误展示其他 Skill。

### Functional Requirements

  slug 重复、缺少主文档、必需值为空或类型非法 MUST 明确失败，不能跳过非法项后称整体成功。

  旧分享链接 MUST 保持身份，复制/下载失败 MUST 明示；平台辅助转换不能取代原件入口。

### Key Entities *(include if feature involves data)*

- **Skill 原件**：单文件或主文档及附件组成的当前内容，保留原始文本、文件字节及内部引用关系。
- **图库记录**：以稳定 slug 关联原件的站内信息；与原件分离，支持显示信息、分类、备注及缺失状态。
- **迁移基线**：四项既有收藏的身份、主文档、受控附件及原始内容清单，用于迁移前后比对。
- **可取用结果**：与某份当前原件对应的可查阅内容、完整主文档和目录包；不得混用其他内容快照。
- **校验诊断**：条目、位置、错误类型及可修正原因；不含秘密值，不把失败伪装成有效结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下使用功能内 `US001-SC-*` 编号，不占用上游 `SC-001～SC-005` 的场景编号。
均为未来实现的通过条件，本次生成规格不代表已经通过业务验收。

- **US001-SC-01**：四项基线收藏全部迁移成功，恰好四个唯一条目；既有 slug 和受控附件保留率 100%。
- **US001-SC-02**：所有有效验收样例的单文件下载及目录包解包后，预期文件路径和文件字节差异为零；
  完整原文复制无缺失字段、代码块或正文，目录包不包含跨 Skill 或项目内部文件。
- **US001-SC-03**：四个既有详情链接在迁移前后均定位同一 Skill，本地等价站点前缀下直接访问、
  刷新和下载全部成功；复制被拒绝和下载不可用两个失败场景均正确提示且零误报成功。
- **US001-SC-04**：所有规定的非法输入样例和缺失本地附件样例均使整次生成失败，
  缺失附件诊断包含具体条目及引用，不提供本次不完整预览或下载；原始文件及上次有效结果变化数为零。
  所有恶意展示/路径样例中，非预期内容执行、越界读取和凭证值回显次数均为零。
- **US001-SC-05**：至少一个仅标准字段样例可独立纳入测试收藏；仅修改站内备注和标签后，
  原始主文档及附件保持完全不变，未知作者、地址和版本均没有被虚构。
- **US001-SC-06**：相同输入在两个干净项目副本中生成后，条目身份、下载原件及附件清单一致；
  不需开发者私人目录、远程管理凭证或生产环境即可完成本轮演示。
- **US001-SC-07**：每类输入错误都提供条目或位置、错误类型和可修正原因；
  维护者无需阅读应用源代码即可确定要修正的内容，同时现有基本浏览及取用流程可继续使用。
