# 工程检查诊断与首版监控边界

日期：2026-11-02；对应初始化步骤 7、NFR-003/NFR-006、DEC-005。
本记录只描述工程检查，不改变 C-01/C-03 的业务 Diagnostic 或运行标识契约。

根安全命令通过 scripts/check-project.js 捕获子进程输出，再输出单个 JSON 对象：

| 字段 | 含义 |
|---|---|
| check | secrets、code、deps；非法调用为 unknown |
| status | passed、failed、error |
| files | 纳入本次检查的候选文件数；依赖检查固定为一个根锁文件 |
| findings | 仅包含安全相对路径、规则编号、级别，以及适用时的整数行号 |
| code | 工具、网络、配置、范围或报告错误的稳定类型；不携带原始错误片段 |

退出码：0 为检查完成且没有阻断级问题；1 为阻断级发现；2 为检查本身失败。
依赖审计 high/critical 阻断，低于此级别仍在 findings 中报告，passed 不表示没有任何发现。
凭证与源码检查的命中均阻断；工具缺失、版本不符、非法规则、未扫描目标和非法 JSON 不得冒充干净结果。

检查器只输出白名单字段并验证类型，不直通原始 stdout/stderr；不输出 Match、Secret、Line、源码片段、
扫描器任意 message 或环境变量。Gitleaks 另以 --redact=100 运行；临时报告和候选快照位于私有临时目录，完成或失败后清理。
目录型/单文件 Skill 均仅作为数据。未纳管 Skill 不自动加入扫描/收录范围；已跟踪公开原件参加凭证检查，
不参加 Lint、测试执行或源码规则扫描。Gitleaks 使用上游默认规则/忽略策略，不能替代后续 C-01 的逐附件凭证策略。

源码检查目前限定自有 assets/scripts JS 与 ESLint 配置，使用本地固定的动态执行、document.write 和 shell exec 三组规则。
测试代码由 Lint/受限测试验证；数据夹具不被执行。该有限规则集不是业务安全验收或完整漏洞证明。

验证见 bootstrap.md 及实际测试：诊断剔除源码/假值、拒绝嵌套字段注入、失败传播、非法规则和受限文件范围。
本轮没有生产日志采集、第三方遥测 SDK、在线可用性探测、告警或 CI；这些继续按后续发布/监控授权实施。
