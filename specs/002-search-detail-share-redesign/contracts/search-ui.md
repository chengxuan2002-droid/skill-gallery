# Contract: 检索、筛选、排序与列表地址

**Feature**: US-002 | **Date**: 2026-11-05 | **Related**: [spec.md](../spec.md)、[data-model.md](../data-model.md)

## 1. 范围

本契约约束列表页的公开行为：关键词、精准/模糊模式、标签/平台/来源/作者筛选、排序、结果状态、
可分享地址和搜索性能。详情路由见 [detail-share.md](detail-share.md)。不新增服务端接口、账户或写入能力。

## 2. 地址契约

### 2.1 列表地址

```text
#/
#/?q=<query>&mode=<fuzzy|exact>&tag=<tag>&platform=<platform>&source=<sourceType>&author=<author>&sort=<auto|name|updated>
```

- 空 Hash 与 `#/` 等价；现有无 Hash 列表访问继续兼容。
- `mode` 缺省为 `fuzzy`；`sort` 缺省为 `auto`。缺省值可以省略，不得改变语义。
- 同一维度重复出现键表示多选，例如 `tag=debugging&tag=workflow`。
- `source` 映射索引的 `source_type`；`author` 与索引作者字符串精确匹配。
- 空值、未知参数、未知筛选值安全忽略；非法 `mode` 回退 `fuzzy`，非法 `sort` 回退 `auto`。
- 查询与筛选值不得包含凭证、token、内部路径或管理信息；编码使用标准 URL 编码。
- 列表状态变化使用 `history.replaceState` 更新地址，不触发整页重渲染；浏览器前进/后退和刷新必须
  从地址恢复有效状态。
- 详情地址始终为 `#/skill/<slug>`，不附加列表参数。进入详情前的列表地址仅保存在当前浏览会话，
  用于“返回列表”；不改变公开详情分享身份。

### 2.2 示例

```text
#/?q=debug&mode=exact&tag=debugging&platform=codex&sort=name
#/?q=%E6%96%87%E6%A1%A3%E8%BD%AC%E6%8D%A2&mode=fuzzy&author=chengxuan
#/skill/handoff-codex
```

## 3. 检索契约

### 3.1 字段

检索 MUST 覆盖公开索引中的：

- 名称 `display_name`
- 简介 `description`
- 标签 `tags`
- 平台 `platforms`
- 作者 `author`
- 来源类型 `source_type`
- 用途/用法 `usage`
- 备注 `notes`
- 正文纯文本 `content_text`

`content_text` 只用于检索，MUST NOT 作为原文展示或下载来源。

### 3.2 模式

| 模式 | 规则 |
|---|---|
| `fuzzy`（默认） | 英文使用 MiniSearch 词项检索、前缀和轻微拼写容错；中文至少按连续子串命中；不承诺语义近义词；不自动纠错精准输入 |
| `exact` | 对规范化文本做连续片段匹配；未加引号的多词查询按完整连续片段匹配；成对双引号界定完整短语；未闭合引号按字面处理并产生确定结果/空结果；不做拼写纠错 |

规范化：Unicode NFC、转小写、空白折叠；不对用户显示规范化后的文本。

### 3.3 相关度

- 名称命中优先于简介/标签，简介/标签优先于正文。
- 模糊模式使用 MiniSearch 字段权重（名称 4、简介/用途/标签 2、其余 1）并合并连续子串命中。
- 精准模式按字段权重计算命中分；同分按 slug 升序。
- 每个输入最多执行一次全库搜索；筛选和排序复用该次结果，不在卡片渲染中重复搜索。

## 4. 筛选与排序契约

- 维度：标签、平台、来源类型、作者。
- 同维度多选为 OR；不同维度为 AND；结果去重。
- 筛选选项来自当前索引实际值；无值维度不渲染空选项；缺失字段不匹配该维度。
- 排序：
  - `auto`：有关键词按相关度；无关键词按 `updated_at` 倒序。
  - `name`：显示名称；缺失时用 slug。
  - `updated`：`updated_at` 倒序；缺失日期的 Skill 排在有效日期之后。
  - 同分/同日期按 slug 升序。
- 用户显式选择 `name`/`updated` 后，查询或筛选变化不得静默改回 `auto`；用户可再次选择或清除全部条件。

## 5. 结果与状态契约

列表 MUST 显示：

- 结果数量（筛选后）；
- 当前查询、模式、筛选和排序的可读条件；
- 清除单个条件/清除全部；
- 结果卡片：名称、一句话用途、标签、平台、版本、更新时间；不堆满作者/来源等详情字段。

状态：

| 状态 | 行为 |
|---|---|
| `loading` | 显示加载状态，不显示空库 |
| `ready` | 显示结果和数量 |
| `empty_library` | 索引存在但没有 Skill；说明原因并提供可恢复动作 |
| `empty_results` | 有 Skill 但条件无结果；保留条件并提供清除 |
| `load_failed` | 索引请求/解析失败；提供重试，不伪装为空库 |

## 6. 可访问与安全

- 搜索输入有可见/可访问标签；模式切换使用真实按钮并暴露当前选择；筛选使用真实 checkbox/button；
  排序使用带标签的 select；卡片使用真实链接。
- 结果数量变化通过 `aria-live="polite"` 通知；焦点在筛选/搜索变化后保留在触发控件。
- 移动端筛选可展开/收起，并正确设置 `aria-expanded`/`aria-controls`。
- 正文外无横向溢出；代码块内部横向滚动。
- 所有公开字段按文本/安全属性插入；不得把查询值拼进 HTML；外部链接仅 http/https。
- 分享参数不含凭证；客户端不向第三方发送查询内容。

## 7. 性能契约

- 负载：1,000 项、总正文 10 MiB 的可复现夹具。
- 方法：数据加载后执行 50 次固定中英查询，记录查询到结果可见的时间；排除网络。
- 目标：p95 ≤ 200ms；记录设备、浏览器和查询集。
- 不达标：先定位搜索/筛选/渲染瓶颈并评估目标，不悄悄改验收；四项数据结果不能替代该测量。
