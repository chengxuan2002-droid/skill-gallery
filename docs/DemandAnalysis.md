## 1. 项目概述

个人精选 Skill 的保存、查找、完整取用、分享和升级管理网站。访客公开读取，管理员维护内容，授权 Agent 可通过命令提交；受支持的开源来源定期检查并自动替换当前版本。

本轮必须形成完整闭环：收录 → 校验发布 → 检索查阅 → 下载分享 → 上游检查 → 新版验证 → 原位替换 → 再发布。分阶段交付不代表可省略上传或自动更新。

| 阶段 | 包含 | 不包含 |
|---|---|---|
| 本轮核心 | 本文 FR-001～FR-011；GitHub 后台、GitHub 首版自动更新、当前单版本并保留 Git 历史已确认 | 访客账户、社交、在线执行 Skill |
| 后续扩展 | 新来源适配、更多安装工具对接 | 未提出的企业协作与计费 |
| 远期 | 有证据后再考虑语义检索、安装端同步 | 本轮不预建接口和基础设施 |

旧设计为历史基线；本轮范围以本文件为准。旧版“不得有服务端”不是用户本轮硬约束；推荐仍以 GitHub 自动化减少运维。

## 2. 术语和概念

| 名称 | 定义 |
|---|---|
| Skill / 原件 | 单文件或完整目录内容，包含可能必需的脚本和相对引用 |
| 站点元数据 | 名称、标签、作者、使用说明等管理信息，与原件独立保存 |
| slug | 同一站内技能的稳定标识；升级不改变分享链接 |
| 声明版本 | 原作者提供的 version；未知则明确显示未声明 |
| 来源修订 | 确定内容来源的提交 SHA；无版本声明也能判定内容变化 |
| 当前版本 | 网站展示、搜索和下载的唯一有效内容 |
| 检查 / 更新 / 发布 | 分别为检查来源、修改当前内容、使网站可读；必须分别报告 |
| 管理员 / 授权 Agent | 有写入权限的维护主体；访客不因知道后台地址而获得权限 |

## 5. 核心功能

以下均为本轮核心。Q-001～Q-004 已由用户确认，其余细节是可执行的设计基线，不代表均经逐条用户审阅。

<a id="fr-001"></a>
### FR-001：保存原件与站点信息

- 目标与输入：保存单 `.md` 文件或包含主文档的目录，同时提供站点元数据。
- 输出：一个稳定 slug 对应一个当前 Skill；原件保留未知 frontmatter 字段、代码块、附件路径和字节内容。
- 规则：名称和简介必填；标签、平台可为空并提示补充，不因缺图库专属字段拒收标准 Skill。Slug 唯一，重复新增返回冲突；显式替换才覆盖。名称、版本与站内分类分别管理。
- 边界：不能把索引文本当原件；作者/版本未知显示“未提供”，不推测作者、不虚构 SemVer。缺主文档、结构非法拒绝，失败不改变现有内容。
- 来源：SC-001/002、R-001/009；验收 AC-001、AC-002。

<a id="fr-002"></a>
### FR-002：多维度、精准及模糊检索

- 输入：关键词、搜索模式、标签、平台、来源类型、作者，以及排序；无关键词时浏览全部。
- 输出：结果卡片、命中数、当前条件和清空入口；按名称、简介、标签、用途、使用说明、正文检索。
- 规则：精准模式对规范化文本做连续片段匹配，双引号可表达完整短语；大小写和空白归一，不自动纠错。模糊模式允许英文轻微拼写误差，中文至少支持连续子串命中，不承诺中文语义近义词。两种模式显式切换，默认模糊。
- 同维度多选为 OR，不同维度为 AND；这有意替换旧版同标签 AND 规则。默认搜索相关度排序，用户显式改名称/更新时间排序后尊重选择。无关键词默认最近更新；同分以 slug 稳定排序。
- 边界：组合查询、清空、空库、空结果均可用；返回列表保留会话条件。URL 保存可分享的查询与筛选参数，不包含凭证。
- 来源：SC-003、BIZ-002；验收 AC-003。

<a id="fr-003"></a>
### FR-003：查阅功能与使用说明

- 输入：详情链接或卡片点击；输出：功能简介、适用场景、使用方法、原文、版本、作者、官方地址、开源地址、更新时间。
- 规则：站点说明与上游原文分区；官方主页和仓库地址分别展示，未知不编造。原文按 Markdown 展示，代码块、表格、列表和有效附件相对链接可阅读；版本未声明时展示来源短修订或内容标识。
- 边界：不执行原文 HTML/脚本；外部地址仅允许安全协议。相对引用缺失给出校验错误或可见提示，不暗中展示其他 Skill 的文件。
- 来源：SC-003；验收 AC-004、AC-012。

<a id="fr-004"></a>
### FR-004：完整取用与稳定分享

- 输入：下载原件、下载完整目录包、复制原文、复制详情链接。
- 输出：单文件保持原文件；目录包以 `<skill-name>/SKILL.md` 为入口并包含附件与许可文件。分享链接延续 `#/skill/<slug>`。
- 规则：原文复制包含 frontmatter；原件下载不得从搜索文本重建。自带说明区分“保存到本地”“安装到 Agent”“执行”，不伪称已安装。平台格式转换如保留，需明确为辅助格式并保留原件入口。
- 边界：目录包不能漏脚本和引用文件；复制失败应报告失败且可手动复制。历史旧链接仍打开对应 Skill；下载失败不能显示成功。
- 来源：SC-002/003、BIZ-001；验收 AC-002、AC-005。

<a id="fr-005"></a>
### FR-005：管理员手动维护

- 输入：管理员上传单文件/目录、修改站点信息、显式替换、下架、配置来源及自动更新开关。
- 输出：可检查的提交、校验结果、发布结果；发布后访客可见。
- 规则：按已确认的 Q-001，复用 GitHub 仓库文件管理与 Actions 作为管理员后台，不另建站内专用后台。目录可按文件夹上传，不要求首版支持上传 ZIP 解压。
- 边界：缺字段给出补充方式；批量上传含非法项时整次发布阻止，已有线上内容仍可读。下架删除当前内容及索引，不处理用户未收录文件。
- 来源：SC-001/002、BIZ-003/004；验收 AC-006。

<a id="fr-006"></a>
### FR-006：Agent 命令提交

- 输入：本地 `.md`、目录或受支持来源定位，加必要元数据；调用者已获管理员授权。
- 输出：结构化结果含 slug、内容标识、变更与发布状态、公开链接或可追踪运行标识。
- 规则：支持校验预览和非交互执行；同内容重复提交为无变更；不同内容同 slug 需显式替换并携带基线修订防覆盖。上传与手动路径使用同一校验规则。
- README 必须包括前提、安装/运行方式、本地与来源示例、元数据格式、认证、替换、预览、退出码、状态查询及排错；示例不含真实凭证。
- 边界：未认证、参数错误、并发冲突返回可区分错误；本地保存成功不得被报告成网站已发布。尚未实现的命令必须标“规划”。
- 来源：SC-001/002、BIZ-003；验收 AC-007。

<a id="fr-007"></a>
### FR-007：公开读取、受限维护

- 访客无需注册或登录，可浏览、搜索、下载、分享；没有公众写入入口。
- 管理员与授权 Agent 才能上传、替换、删除、改来源、触发更新与发布；身份复用 GitHub 仓库权限和已有 Git/gh 授权（Q-001 已确认）。隐藏按钮或后台路径不是权限校验。
- 原件仅作为数据处理，收录及自动更新均不执行其脚本；凭证只在受信任环境，不能进入页面和公开产物。权限失败不产生写入副作用。
- 来源：BIZ-004、安全约束；验收 AC-008、AC-012。

<a id="fr-008"></a>
### FR-008：来源检查与自动升级

- 输入：每个 Skill 的来源定位、跟踪策略和 enabled 开关；定时或管理员手动触发。
- 输出：无变化、已更新、失败或冲突；新版发布后同一 slug 仍只有一个条目。
- 首版自动更新来源为 GitHub 公开仓库文件/目录（Q-002 已确认）；支持跟踪指定分支或稳定 Release，固定提交可只检查不自动前移。普通网址不是足够的自动更新配置。
- 规则：先完整获取并验证候选，再原位替换；上游删除的附件也删除。版本标签与内容变化分开：按修订/内容识别变化，版本未变也可能更新；同内容不同提交仅记录检查，不伪造内容升级。Release 策略跟随最新非草稿、非预发布的已发布 Release，不自行猜测跨项目 SemVer。
- 站内标签、备注、分类及来源配置不被同步覆盖；同步内容被本地修改时返回冲突并保留当前版本，由管理员决定恢复跟踪或转自维护。
- 单一当前版本按已确认的 Q-003：当前树、索引和下载仅有新版，允许保留 Git 历史用于恢复，不提供公开旧版入口。上游 404、改私有、限流、超时、许可信息变化/缺失或无效候选均不删除当前版本；许可变化暂停替换并报告。
- 检查周期建议每日一次，候选时间为上海时间 03:17；尚未确认，不承诺调度 SLA。提供开关与手动重跑；不因长期无变化伪造空提交维持调度。
- 来源：SC-004/005、BIZ-005；验收 AC-009、AC-010、AC-011。

<a id="fr-009"></a>
### FR-009：维护结果与恢复

- 管理员可查看每项最近检查、最近成功更新、来源修订、结果和错误原因，并能重跑；无变化同样记录真实检查时间。
- 提交、同步完成和部署完成分开显示。网站可展示该内容最近同步时间；后台详细错误不必公开。
- 单技能失败不阻止其他技能候选检查；有效变更可一起提交，但全量构建失败则整批不发布。部署失败维持上次正常站点，可从受控历史恢复；按已确认的 Q-003 保留 Git 历史，通过受控恢复提交重新发布。
- 来源：SC-005；验收 AC-010、AC-011。

<a id="fr-010"></a>
### FR-010：简洁且有科技感的界面

- 列表以搜索和分类为中心，卡片显示名称、一句话用途、标签、平台、版本及更新信息；作者与来源可在详情充分显示，避免卡片堆满字段。
- 详情首屏放名称、简介、版本、作者、来源，以及下载/复制链接；其次为功能与用法、原文和附件。
- 推荐中性背景、清晰边框、单一蓝紫强调色、有限渐变与轻动效，支持明暗模式；不用粒子背景、自动播放视频或大面积霓虹干扰阅读。中文版界面、英文技术名保留，作为本轮拟议呈现方案。
- 桌面左筛选右结果，手机使用折叠筛选与单列卡片。加载、空库、空结果、错误和窄屏代码块均有明确状态。
- 来源：BIZ-006；验收 AC-013。

<a id="fr-011"></a>
### FR-011：迁移、构建与原地址发布

- 原部署地址及已有详情链接不变；保留已收录的四项及附件，迁移前后能逐项核对。
- 从原始文件重建数据，不从有损索引迁移正文；未跟踪 `office2md` 不自动作为已收录数据处理，应单独验证并报告。
- 校验失败不发布残缺索引。修改后自动构建静态产物并发布，维护者不必手工更新搜索索引。
- 发布必须确保页面、索引、正文、下载包来自同一内容快照；失败维持既有线上版本；旧路由、子路径和缓存版本均纳入验收。
- 来源：BIZ-007、存量兼容；验收 AC-001、AC-014。

## 6. 扩展功能

GitHub 之外的 URL/Gist/其他平台来源适配、更多安装工具连接、批量元数据补全，均在有真实样本后扩展。非 GitHub 内容仍能手动收录，自动更新状态应显示未配置或不支持，不伪称已覆盖。

## 7. 远期边界

本轮暂无社区共建体系。访客账户、评论、点赞、付费、全网抓取、向量数据库、在线运行 Skill 不纳入实施任务。

## 9. 关键流程

正常收录：管理员/Agent → 授权 → 输入与原件校验 → 预览 → 提交 → 全量构建 → 部署 → 返回可读链接。

自动升级：定期/手动触发 → 锁定来源修订 → 下载目录与许可 → 对比 → 校验候选 → 检查当前基线 → 替换整个目录 → 构建 → 提交并发布 → 报告。

失败链：获取失败保留原件；候选非法保留原件；当前基线变化返回冲突；构建失败不提交新当前版；部署失败保留上次站点并报告“提交已完成、部署失败”，允许按同一提交重跑。

## 10. 业务数据与生命周期

| 实体 | 属性与归属 | 生命周期 |

## 13. 验收标准

每条 Given/When/Then 都是验收契约；当前执行状态按故事记录在 `specs/*/validation/`，不因本文档更新而视为全部已通过。

<a id="ac-001"></a>
**AC-001 数据与迁移（FR-001、FR-011）**：Given 既有四项原文件及目录和一个仅标准字段的合法 Skill，When 在隔离目录迁移构建，Then 四项 slug 和附件保持，新增标准 Skill 可补站内元数据入库；原始文件 digest 不变。缺主文档/同 slug 重复时非零退出，不生成可部署残缺站点。

<a id="ac-002"></a>
**AC-002 保真取用（FR-001、FR-004、NFR-001）**：Given 包含 `>-`、嵌套元数据、代码块、中文、表格、附件与许可的夹具，When 复制原文或下载原件/目录包，Then 原文一致，解包后所有路径及字节一致、入口层级正确；原版本及未知字段不丢失。

<a id="ac-003"></a>
**AC-003 搜索（FR-002）**：Given 名称含 `debugging`、中文用法含“文档转换”的样例及多标签数据，When 精准搜索 `debug`、短语或模糊搜索 `debuging`、中文子串并组合作者/平台/来源，Then 按定义命中、精准不纠错、同维 OR/跨维 AND，显式排序生效，空结果可清除，分享查询后条件能恢复。

<a id="ac-004"></a>
**AC-004 详情（FR-003）**：Given 信息齐全及作者/版本缺失的两项，When 打开详情，Then 展示功能、用法、原文、版本/修订、作者、官网/仓库；缺失明确提示，代码表格可读，相对附件正确；未知 slug 显示可返回的未找到状态。

<a id="ac-005"></a>
**AC-005 分享与复制（FR-004）**：Given 旧 Hash 链接，When 替换同一 Skill 并重新打开、下载或复制链接，Then 链接不变且读取新版；模拟剪贴板拒绝时提示失败并可手动复制，不能误报成功。

<a id="ac-006"></a>
**AC-006 手动维护（FR-005）**：Given 按 Q-001 使用 GitHub 后台且管理员已授权，When 按 README 上传文件和目录、编辑元数据、替换或下架并运行校验，Then 有可追踪结果，发布后新增/替换/下架正确；非法上传不破坏已有线上内容。

<a id="ac-007"></a>
**AC-007 Agent 提交（FR-006、NFR-006）**：Given 干净 checkout、测试凭证及本地 Skill，When 仅依 README 先预览再非交互提交、重复提交、替换并查询状态，Then 预览无写入、成功可查、重复不多建提交、基线不符报冲突，退出码与输出明确区分提交和部署。

<a id="ac-008"></a>
**AC-008 权限（FR-007）**：Given 未登录访客、无权限与授权身份，When 分别读取公开内容、尝试上传/删除/触发更新，Then 访客可读、未授权无写入副作用、授权可维护；浏览器存储、产物和日志无凭证。

<a id="ac-009"></a>
**AC-009 自动替换（FR-008、NFR-001）**：Given 测试来源的两个修订，第二版新增一个文件且删除旧脚本，When 分支或 Release 策略检测并应用新版，Then slug 不变、列表一项、当前树/下载包无旧脚本且有新文件、站内备注不丢；上游声明版本未变仍能按内容变化更新；相同内容不重复升级。

<a id="ac-010"></a>
**AC-010 失败与冲突（FR-008、FR-009、NFR-004）**：Given 超时/404/限流/非法候选/许可变化/本地修改夹具，When 检查或并发提交，Then 每种情况有明确状态，当前版不被覆盖；一个来源失败不妨碍其他来源检查；整体构建失败不发布，重跑幂等。

<a id="ac-011"></a>
**AC-011 状态与恢复（FR-009）**：Given 无变化、有更新、提交成功部署失败三次运行，When 管理员查看记录及重跑，Then 可区分检查/更新/部署时间和结果，知道失败点；可按已提交内容重新发布且不重复覆盖；按 Q-003 利用 Git 历史生成恢复提交并重新发布上次有效内容。

<a id="ac-012"></a>
**AC-012 内容边界（FR-003、FR-007、FR-008、NFR-003）**：Given 带 HTML 事件、`javascript:` URL、越界路径、符号链接及可执行脚本的夹具，When 上传、构建、浏览与打包，Then 不执行脚本、拒绝越界及链接型文件、清理活动内容；合法附件保持字节完整；下载的脚本仅作为文件。

<a id="ac-013"></a>
**AC-013 界面（FR-010、NFR-005）**：Given 空库、正常和错误状态，When 在 360/768/1440px、明暗主题及键盘操作下浏览，Then 搜索/筛选/详情/下载可达、焦点可见、正文外无溢出、正文对比至少 4.5:1；移动筛选能展开收起，减少动效偏好有效。保留截图与操作记录。

<a id="ac-014"></a>
**AC-014 构建与部署（FR-011、NFR-004、NFR-006）**：Given 干净 checkout 和模拟部署失败，When 执行声明的锁定依赖构建及更新后发布链，Then 生成白名单静态产物、内容与索引同快照；旧地址、子路径资源、四个旧深链接与刷新可用；失败不替换正常站点，自动提交后的发布不依赖隐含 push 触发。

<a id="ac-015"></a>
**AC-015 性能（NFR-002）**：Given 1,000 项、总正文 10 MiB 的可复现夹具，When 在记录型号的设备与浏览器上加载后执行 50 次中英查询，Then 报告 p95，候选通过线为 200ms；不含网络，不能拿四项数据结果代替该测量。若不达标，先分析并评估目标，不能悄悄改验收。
