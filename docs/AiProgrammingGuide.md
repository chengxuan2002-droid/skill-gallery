### 3.3 编码约定

- 遵循现有 CommonJS 构建代码风格，前端按现有风格做必要拆分；不全库格式化。模块目录与接口以技术文档 M-01～07/C-01～07 为唯一清单。
- 新字段优先放图库记录，不重写第三方 frontmatter。YAML 解析支持标准折叠、多行和嵌套元数据；schema 缺失与类型错误应区分，不吞掉错误。
- 用户可见错误有可恢复动作，CLI 错误有稳定类型。stdout 为机器 JSON 时不要夹杂构建进度，stderr 脱敏；前端复制必须等待成功，不能调用后立即 toast 成功。
- 目录替换先准备候选后切换，清除旧附件；所有输入路径做边界验证，不能跟随符号链接或把上游文件作为应用代码加载。
- 前端用 DOM 文本/属性 API 或正确上下文的转义；清理后 HTML 才能渲染，不能认为 `textContent → innerHTML` 自动适合所有属性上下文。
- 产品依赖只用于需要的成熟能力：YAML、Markdown、安全清理、搜索、打包；开发依赖可用于已授权的测试、Lint/格式和安全检查，精确锁定并与产品依赖分开。不手写完整解析器，也不为本轮加框架、数据库、登录系统或消息队列。
- 构建输出只在 dist；原件、图库记录为输入。同步状态不放多个版本目录，运行日志不冒充公开的版本历史。
- URL 始终考虑 `/skill-gallery/`，禁止把 `/assets/...` 等根路径当项目路径。详情链接与查询参数分别编解码。
